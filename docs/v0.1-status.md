# v0.1 Status — Phase 1 (stabilized core + CLI)

Standalone Midnight only: no Dots work, embeddings, cloud, SDKs or UI in this phase.

## Completed (verified by the tests listed below)

- [x] `init` — creates the database and applies migrations; idempotent (`tests/cli_smoke.rs`).
- [x] `index` — incremental, `.gitignore`-aware (smoke test edits a file, re-indexes, old content disappears; ignored dir not searchable).
- [x] `search` — now accepts a positional query as well as `--query`.
- [x] `memory add|get|list|delete|search` — `--namespace` (alias `--scope`); `get` is new (`memory::get_memory`).
- [x] `doctor` — checks open, SQLite version, FTS5, integrity; non-zero exit on failure.
- [x] `--json` accepted on every command (global). Legacy commands always emitted JSON; `init`, `doctor` and `memory *` print text by default and JSON with `--json`.
- [x] Namespace isolation: cross-namespace `get` and `delete` fail (smoke test).
- [x] Persistence across processes (each CLI call is a new process).
- [x] Existing commands, MCP stdio/HTTP, retrieval code and frozen suites are unchanged.

## Remaining blockers / risks

- Indexing cancellation safety and resource bounds rely on the existing implementation and its unit tests; Phase 1 added no new CLI-level cancellation test (SIGINT).
- Migration safety on databases from older schema versions was not re-tested here beyond the existing suite.
- `memory add` exposes content, kind and source URI only; temporal validity fields remain on the legacy `remember` command.
- Native macOS retrieval gate in `docs/retrieval-v04.md` is still pending.
