## Phase 2 deliverables

- [x] `multilingual-e5-small` via FastEmbed-rs (384 d, mean pooling, L2-normalised, `query:`/`passage:` prefixes, 512-token limit); lazy loading; never downloads outside `models pull`; offline inference verified with a dead proxy and `HF_HUB_OFFLINE=1`.
- [x] Persistent vectors for memories and code chunks in SQLite (schema 6) with model name, revision, dimensions and source hash; incremental `embed`; stale/other-model vectors removed; trigger cleanup on delete/forget/file change.
- [x] Exact KNN (no ANN, no sqlite-vec) + FTS5/BM25 with deterministic RRF (k=60, ascending-key tie-break); scope, model identity and live-row predicates are in the SQL.
- [x] CLI: `models list|pull`, `embed --namespace/--repo`, `memory search --mode`, `search --mode`. Default `lexical` keeps legacy JSON unchanged. Missing model/vectors degrade to lexical with `degraded`, `notice` and a stderr warning.

## Remaining risks and blockers

- **ONNX Runtime distribution (release risk).** `ort` ships no prebuilt binary for macOS x86_64, and the 2.x line requires ONNX Runtime ≥ 1.24, which Microsoft does not publish for that target. The build therefore pins `fastembed =5.13.0` (ort rc.11, runtime ≥ 1.22) and loads the library dynamically. Users must provide `libonnxruntime` (`ORT_DYLIB_PATH` or the documented locations); `models pull` does not fetch it. Not tested on Apple silicon, Linux or Windows here. A packaging decision (bundle the runtime per platform) is needed before release.
- Dependency footprint grew (343 packages, was 175; `tokenizers`, `ort`, `ureq`, `native-tls`…). Release binary 15.0 MB. `THIRD_PARTY_LICENSES.json` regenerated; the model (MIT) and ONNX Runtime (MIT) licenses are not yet in the inventory.
- `models pull` resolves `main` and records the resulting commit; the revision is not pinned in source.
- Embedding throughput not benchmarked formally. Observed (CPU, x86_64 Mac, release): ~1,450 code chunks plus 2 memories in a few minutes with other work running; searching with a loaded model costs seconds (model load per process). Exact KNN scans every vector in scope; no scale measurements were taken beyond ~1.5k vectors, so no performance claim is made.
- Memory-search `candidate_coverage` for semantic-only hits is reported as `complete` over *embedded* rows; incomplete embedding coverage is reported separately (`semantic_coverage`, `notice`).
- Embeddings are only created by explicit `embed`; `memory add` and `index` do not embed (by design, to keep them model-free). Callers must re-run `embed` after changes.
- MCP/HTTP tools do not expose semantic modes yet (CLI only).
- Native macOS retrieval gate in `docs/retrieval-v04.md` is still pending.
