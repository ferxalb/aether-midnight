Binary copied to an empty directory and run under `env -i` (`PATH=/usr/bin:/bin`, no cargo, no

## P0 detail

**ONNX Runtime.** Microsoft's last macOS x86_64 release is 1.23.2 (later releases are arm64 only),
and `ort` ships no prebuilt library for that target. Midnight therefore pins 1.23.2 and loads it
dynamically; it is never bundled in Midnight binaries. The pin (URL, size, archive SHA-256
`d10359e1…85a6`, library SHA-256 `8c9c78de…c054`) lives in `src/runtime.rs`; the archive digest
equals the digest GitHub publishes for the release asset and the SHA-256 computed independently from
a separate download. Install, lookup order, and diagnostics: [embeddings.md](embeddings.md#onnx-runtime).
Provenance limits: trust anchors are Microsoft's GitHub release plus the hashes reviewed in this
repository; the library is not code-signed or notarised by Midnight, and macOS Gatekeeper behaviour on
a quarantined download is untested (the file is fetched by Midnight, which does not set the quarantine
attribute).

**Model.** `intfloat/multilingual-e5-small` @ `614241f622f53c4eeff9890bdc4f31cfecc418b3` (MIT per its
model card). `onnx/model.onnx` and `tokenizer.json` pin to the Hugging Face LFS ids; the three small
files were hashed after download. Cached snapshots of any other revision are ignored. Existing Phase 2
databases embedded under a different revision string are treated as a different space: search degrades
with an explicit notice and `embed` re-embeds.

**Licence inventory** (`THIRD_PARTY_LICENSES.json`, schema 2, regenerated with
`midnight-harness license-inventory --force`): 375 crates (was 343) — new this phase: `rainy-sdk`
(Apache-2.0), `reqwest` 0.13 (MIT OR Apache-2.0), `aws-lc-sys`/`aws-lc-rs` (ISC, Apache-2.0, MIT and BSD-3-Clause
components; combined expression recorded), `rustls-platform-verifier`, `webpki-root-certs`
(CDLA-Permissive-2.0), `secrecy`, `futures`. Copyleft check: no GPL/AGPL; `option-ext` is MPL-2.0
(pre-existing, unmodified); two `r-efi` copies offer `MIT OR Apache-2.0 OR LGPL-2.1-or-later` (the
permissive options apply). `non_crate_components` records ONNX Runtime (MIT, with its own
ThirdPartyNotices copied beside the library on install), the model weights (MIT, files and hashes),
and the two remote services (no redistribution). Model citation: Wang et al., arXiv:2402.05672. This is
an engineering inventory from package metadata, not legal advice; `ThirdPartyNotices.txt` of ONNX
Runtime was installed but not individually audited.

## P1 detail

**`rainy-sdk` 0.6.51 evaluation → adopted as the single transport for both providers.**

| Question | Finding |
| --- | --- |
| Toolchain | `rust-version = 1.98`, edition 2024; builds on 1.99.1. Midnight now declares `rust-version = "1.98"` (README previously said 1.85) |
| Dependencies | +32 locked packages (`reqwest` 0.13, `rustls`/`aws-lc-rs`, `quinn` via reqwest, `secrecy`, `futures`, …); `tokio` was already present. `aws-lc-sys` compiles C, so a C compiler is needed. Release binary 15.0 → 19.5 MB. A second TLS stack (rustls) now sits beside the existing native-TLS one used by `ureq`/Hugging Face downloads |
| OpenRouter contract | OpenAI-compatible `POST {base}/embeddings`, Bearer auth, `dimensions`, `encoding_format`, `input_type`, `provider`, `user` — all expressible through the SDK's typed fields plus `extra` (verified against OpenRouter's published OpenAPI document) |
| Rainy contract | `AuthConfig::with_api_base_url` + `create_embeddings`; the SDK's own default endpoint is used unless `--endpoint` is given |
| Safety properties | no redirects, timeout, bounded bodies (8 MiB / 64 KiB), `SecretString`, key redaction in errors; loopback HTTP allowed only for tests |
| Gaps found | (1) 402 without an `INSUFFICIENT_CREDITS` code reaches us as a generic 4xx, so Midnight recognises it by message text (`credit`/`payment`/`billing`/`balance`); (2) the SDK requires `usage` and `data[].index` in the response although OpenRouter's schema marks both optional — a provider that omits them is reported as malformed (fail closed); (3) async API, so Midnight runs a private current-thread tokio runtime per embedder |
| Why not a hand-written adapter | A ~150-line `ureq` adapter would avoid the extra stack, but would duplicate the redirect, body-limit, redaction and error-mapping work the SDK already provides and tests, and the task prefers reuse. Revisit if the footprint or gap (2) matters more than that reuse |

Implemented: `--provider local|openrouter|rainy`, `--model`, `--dimensions`, `--endpoint`,
`--timeout-secs`, `--param` on `embed` and on `--mode semantic|hybrid` searches; credentials from
`OPENROUTER_API_KEY` / `RAINY_API_KEY` only; document and query embedding; batches of 16; responses
placed by `index`; strict dimension/finite/zero-vector validation; bounded, redacted errors; no
automatic retry; isolation by `provider:model` + endpoint/parameter fingerprint + dimensions; query
never embedded in a mismatching space; `embed` after any change replaces the scope's old space;
failures degrade search to lexical (`degraded`, `notice`, stderr warning) and leave committed vectors
intact when `embed` stops part-way. Embedding stays explicit — no auto-embed on write.

## Deployment blockers and release risks

No P0/P1 blocker remains for the macOS x86_64 target. Remaining risks, in rough order:

1. **No live cloud validation.** OpenRouter/Rainy request and response handling is verified against
   the published contracts and a mock only. Run the ignored live smoke with real credentials before
   announcing cloud support; gap (2) above is the most likely surprise.
2. **Footprint and build requirements.** +32 packages, a C toolchain for `aws-lc-sys`, MSRV 1.98, two
   TLS stacks, +4.5 MB binary.
3. **Single-platform runtime pin.** Other platforms need `ORT_DYLIB_PATH` (accepted if it loads and is
   ≥ 1.22, but unverified by Midnight). An arm64 macOS pin is a one-line table addition once someone
   tests it.
4. **Unsigned dynamic library** installed under the user's data directory; integrity rests on the
   SHA-256 pins and the hash re-check at load for managed installs only.
5. **Query latency of the CLI path** with the local model (≈ 4 s per fresh process). Semantic modes are
   not exposed through MCP/HTTP (out of scope this phase).
6. **Provider-side data handling.** Selected providers receive the text; retention is theirs. Documented
   in [privacy.md](privacy.md).
7. A scope holds one embedding space; switching providers deletes the previous vectors on `embed`
   (by design; documented, reported as `replaced_other_model`).
8. Native macOS retrieval gate in `docs/retrieval-v04.md` is unchanged (still pending).
