Seventh prerelease of AETHER Midnight. It replaces rc.6 as the candidate for the v0.1.0 stable
decision because it changes the database schema and the MCP memory contract; those changes need a
published prerelease before stable. Stable readiness depends on validating this candidate; it is
not automatic.

**Install** (macOS, Universal 2, user-local, no sudo; available after publication):

```sh
curl --proto '=https' --tlsv1.2 -fsSL https://github.com/ferxalbs/aether-midnight/releases/download/v0.1.0-rc.7/install.sh | sh -s -- --no-runtime
```

Already installed? After publication, run `midnight update`.

**Database: schema 7 → 9.** The first rc.7 run migrates the database in one transaction. rc.6 and
older binaries then refuse it (`database schema 9 is newer than this binary supports`). To keep the
option of going back, copy the database before the first rc.7 run, for example
`sqlite3 midnight.sqlite3 ".backup 'midnight-before-rc7.sqlite3'"`. No dependency changes.

## Changes since rc.6

**Agent memory**

- MCP memory calls that omit `scope` use `project:<repository directory name>`, the repository the
  code tools already default to. A policy that pins one scope still wins, a scope list that
  excludes the default still requires an explicit scope, and an explicit scope is never replaced.
  Before, such a call failed with `missing string argument scope`.
- The `initialize` instructions tell the agent when to recall and when to remember, how to store a
  source and then a derived fact that cites it, how to supersede a fact, and which scope applies.
- New MCP tools: `get_memory` (one memory by id, within its namespace) and `list_scopes`
  (namespaces with active memories, filtered by policy, plus `default_scope`). `list_memories`
  accepts `offset` and `kind`.
- `remember` and `remember_batch` embed the memories they just stored when a provider is
  configured and permitted, under the same rules as `index_repository` (policy remote grant, saved
  provider-bound consent, project `embeddings: false`). `remember` adds `embedding` or
  `embedding_notice`; `embed: false` skips it; a failure never undoes the write. Remote write-time
  embedding uses one attempt with a five-second timeout.
- With the local provider, one MCP connection loads the model once. rc.6 loaded it again for every
  query that missed the query-vector cache.
- CLI: `memory scopes`, `memory list --offset --kind`, `memory export` (JSON Lines, new owner-only
  file, never overwrites) and `memory import` (one transaction; ids, source links and supersession
  links remapped; `--namespace` to retarget).
- `connect --with-instructions` adds a marked block to the project's `CLAUDE.md` (Claude Code) or
  `AGENTS.md` (Codex) and `--remove --with-instructions` takes it out. Text outside the block is
  never changed; an existing file is backed up under `.midnight/backups/`.

**Speed and storage** (results unchanged; paired numbers in
[performance](../performance.md), sections 2026-11-11 and 2026-11-12)

- Exact-symbol candidates use the `code_symbols_name` index instead of probing every file of the
  worktree on each `search_code`.
- MCP read-only code tools and semantic/hybrid recall reuse the session's SQLite connection.
- Exact KNN selects the top k without sorting every hit and reads vectors without copying them.
- Schema 8 drops an index that duplicated the `UNIQUE(repo_id, worktree_id, rel_path)` index
  (about 9.5% smaller database on the generated 10k-file fixture).
- Schema 9 adds a trigram index of file paths. Every `search_code` looked for the query inside
  every path of the worktree; queries of three or more characters now read the index and then
  apply the same check, so results are unchanged. On the 10k-file fixture lexical `search_code`
  p50 went from 3.1–4.2 ms to 0.5–1.3 ms; the database grows about 2.9% and a full index takes
  about 7% longer.

## Compatibility and privacy

- `remember` and `remember_batch` now advertise `openWorldHint: true`. With a configured remote
  provider and saved upload consent they send the text of the stored memories to that provider,
  as `embed --namespace` does. `midnight mcp --local-only`, HTTP tokens without
  `--allow-remote-embeddings`, project `embeddings: false` and `embed: false` prevent it.
- A memory call that relied on the missing-scope error to catch a bug now stores into the default
  project namespace. Pass `scope` explicitly, or pin one with `--memory-scope` or
  `mcp.memory_scopes`, to keep strict behavior.
- `remember` responses may carry the additive `embedding`/`embedding_notice` fields;
  `remember_batch` responses keep their array shape. `recall` keeps its lexical default and shape.
- The code retrieval contract of rc.6 is unchanged: same candidates, ordering and output.

## Validation and stable decision

The implementation passes `cargo fmt --check`, strict all-target/all-feature Clippy and
`cargo test --locked`; new tests cover the default scope and policy interaction, write-time
embedding and its failure and consent paths through a real MCP process with the loopback mock,
export/import round trips with links and atomic failure, the instructions block, the schema 8 and 9
migrations, the trigram path candidates against an ASCII-folding oracle (Unicode, quotes, short
queries, deletes and renames) and the partial top-k equivalence. Frozen code and memory quality suites produce
identical output, in both insertion orders for memory.

Measurements so far come from a Linux x86_64 cloud container with a loopback embedding endpoint.
**Not yet measured:** local-model reuse (no pinned ONNX Runtime on that host), the native macOS
numbers and a large real repository. The procedure is in the
[macOS benchmark guide](../macos-benchmark-guide.md#rc7-validation). Real-client checks of the new
memory workflow (Claude Code, Codex) are open.

Before deciding stable, validate the published rc.7 artifact as listed in the
[checklist](../release-checklist.md). Known boundaries of rc.6 remain: unsigned/not-notarized
distribution, explicit fallback on provider outages, untested arm64 runtime, pending live Rainy
validation, and experimental Linux and Windows. rc.5 and rc.6 notes also apply when upgrading from
an older candidate; see [rc.6 notes](v0.1.0-rc.6.md).
