Fourth prerelease of AETHER Midnight: a local-first engine for deterministic code search and explicit agent memory.

**Install** (macOS, Universal 2, user-local, no sudo):

```sh
curl --proto '=https' --tlsv1.2 -fsSL https://github.com/ferxalbs/aether-midnight/releases/download/v0.1.0-rc.4/install.sh | sh -s -- --no-runtime
```

Already on rc.3? Run `midnight update`.

**Read before upgrading: database schema 7.** The first run migrates your database in place (one transaction, data kept). A schema 7 database cannot be opened by rc.2 or rc.3, which refuse it as "newer than this binary supports". Back up the database file first if you may go back.

**Changes since v0.1.0-rc.3**

- **Correction:** the rc.3 notes said `embed` re-sent only changed chunks. It did not: editing one line re-embedded the whole file (measured: 19 chunks for a one-line edit). This release does what rc.3 claimed. The same one-line edit now embeds 1 chunk and reuses 212; an unchanged repository embeds 0. Inserting or deleting lines still shifts the later fixed-size chunks, which are then re-embedded.
- Code tools no longer start `git` on every call: the repository identity is read from `.git` (same ids as before; `git` is still used for unusual layouts). Median latency of `open_range`, `index_status` and `search_code` on a 383-file repository went from about 128 ms to about 2 ms (different builds, one machine, 10 calls: indicative, not a benchmark).
- MCP: when the server runs inside a Git repository, `repo_path` is optional and defaults to the nearest repository root above the working directory (never your home directory or `/`).
- MCP: `initialize` echoes the client's protocol version (2025-11-25, 2025-06-18, 2025-03-26 or 2024-11-05) and every tool carries read-only, destructive and idempotent annotations.
- Linux and Windows are documented as **experimental**; macOS is the supported platform.

**Known limitations**

- The binary is **not Developer ID signed or notarized**; Gatekeeper rejects it.
- Tested through scripted MCP sessions only: Claude Code, Claude Desktop and Codex have **not** been run against this build.
- Rainy embeddings have **not** been verified against a real account. OpenRouter was verified by hand, including the incremental re-embedding above.
- Tested on an Intel Mac; the arm64 slice is built and packaged but was not run by the maintainer.
- A single file that fails to parse keeps a repository marked `complete: false`.
- Two processes writing to the same database at once can fail with `database is locked`.
