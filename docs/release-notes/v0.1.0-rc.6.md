Sixth prerelease of AETHER Midnight, intended as the final release candidate before evaluating
v0.1.0 stable. Stable readiness depends on validation of this candidate; it is not automatic.

**Install** (macOS, Universal 2, user-local, no sudo; available after publication):

```sh
curl --proto '=https' --tlsv1.2 -fsSL https://github.com/ferxalbs/aether-midnight/releases/download/v0.1.0-rc.6/install.sh | sh -s -- --no-runtime
```

Already installed? After publication, run `midnight update`.

**Database:** schema remains 7. No migration or dependency change is introduced by rc.6.

## Changes since rc.5

- MCP `search_code` supports `lexical`, `semantic`, and `hybrid`. Without saved provider settings
  it stays lexical; with a configured, permitted provider it defaults to hybrid. Activating
  OpenRouter with saved provider-bound consent enables that default. Explicit lexical stays
  offline. MCP `recall` keeps its lexical default, with explicit current-time semantic/hybrid.
- `index_repository` incrementally updates embeddings when configured and authorized. Provider
  failure preserves completed lexical indexing and adds an actionable `embedding_notice`.
- Code lexical retrieval adds a separate, bounded, verified literal-phrase candidate lookup,
  including phrases in long files. Hybrid prioritizes fresh exact paths/symbols, then verified
  literal phrases, then other candidates, with RRF within each class. Memory ranking is unchanged.
- MCP connections reuse up to 32 query vectors for 60 seconds. Keys include scope, full model
  identity and a query hash; no query plaintext is stored by the cache. Expired entries are
  removed lazily on the next cache access or connection close. Results and source freshness
  are checked anew on every request.
- Interactive remote MCP queries use one attempt with a five-second transport timeout and
  explicit lexical fallback. Bulk embedding retains its retry policy.
- The measurement harness now prepares reverse fixtures in dependency-compatible order rather
  than panicking when a derived memory precedes its source. Invalid dependencies return errors.

## Compatibility and privacy

- Hybrid reports `fusion: "literal-priority+rrf(k=60)"` and protected `evidence_class` metadata.
  Raw RRF scores are not globally descending across classes: consumers must preserve response
  order. Literal phrases add `literal_phrase` to lexical match explanations.
- Configured code-search defaults can change MCP output from a lexical response to one carrying
  mode/coverage/degradation metadata. Request `mode: "lexical"` to retain the lexical shape.
- Remote MCP calls require saved provider-bound consent; agents cannot select a provider,
  endpoint, model or credentials, or grant consent through tool arguments. HTTP tokens also
  require `--allow-remote-embeddings`; existing tokens deny remote use. Stdio supports
  `--local-only`. Search sends queries; authorized indexing sends eligible source chunks.
- `index_repository`, `search_code`, and `recall` advertise `openWorldHint: true` because their
  configured behavior can contact a provider. Existing tool/root/namespace restrictions apply.
- Historical memory recall and `broad_terms: recent` remain lexical; incompatible explicit
  semantic/hybrid requests fail before a provider call.

## Validation and stable decision

The implementation entering rc.6 passed 210 automated tests, with zero failures and three
ignored, strict all-target/all-feature Clippy, formatting and a locked release build. Automated
cloud tests use a deterministic loopback mock. In three manual paired OpenRouter CLI runs, the
literal target moved from hybrid ranks 12/12/11 to 1/1/1. All four frozen memory suites preserve
their complete quality objects in both supported insertion orders. Frozen code MRR/recall are
unchanged; four phrase queries per strategy intentionally reorder two equally relevant files.

The extra phrase lookup adds work; some diagnostic classes got slower. There is no universal
latency improvement claim. See [reviewed evidence](../hybrid-mcp-validation.md) and the
[full retrieval/privacy contract](../hybrid-mcp.md).

Before deciding stable, validate the published rc.6 artifact with real MCP clients, installation
and update flows, and the platform/signing expectations in the [checklist](../release-checklist.md).
The tag workflow and published-artifact checks are not established by local source tests.

Known boundaries remain: bounded candidate windows and token budgets, variable remote embeddings
outside cache reuse, explicit fallback on outages, unsigned/not-notarized distribution, and
platform/client gates not closed by this campaign. Linux and Windows remain experimental;
packaging an architecture does not establish runtime validation on that architecture. Live
Rainy validation is still pending. rc.5 field migrations also apply when upgrading from an
older candidate; see [rc.5 notes](v0.1.0-rc.5.md).
