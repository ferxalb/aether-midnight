Eighth prerelease of AETHER Midnight. It replaces rc.7 as the candidate for the v0.1.0 stable
decision. It ships the whole v0.2 development line (Parts 1 and 2) as one release: token-saving
search results, a file watcher, a single-writer daemon, memory provenance (schema 10) and
symbol-aware embeddings. Stable readiness depends on validating this candidate; it is not automatic.

**The macOS binary is not Developer ID signed and not notarized.** Gatekeeper rejects it; see
[installation](../installation.md#gatekeeper). Nothing was done to bypass that.

**Install** (macOS, Universal 2, user-local, no sudo; available after publication):

```sh
curl --proto '=https' --tlsv1.2 -fsSL https://github.com/ferxalbs/aether-midnight/releases/download/v0.1.0-rc.8/install.sh | sh -s -- --no-runtime
```

Already installed? After publication, run `midnight update`. The archive SHA-256 is produced by the
release workflow and published as the `.sha256` asset; it is intentionally not written here.

**Database: schema 9 → 10.** The first rc.8 run migrates the database in one immediate transaction. rc.7 and
older binaries then refuse it (`database schema 10 is newer than this binary supports`). Copy the
database before the first rc.8 run if you may go back, for example
`sqlite3 midnight.sqlite3 ".backup 'midnight-before-rc8.sqlite3'"`. Memory JSONL exports from rc.7 still import. Legacy records default to `agent`.

## Changes since rc.7

**Search results (MCP contract change; details and old/new examples in [api](../api.md))**

- `search_code` returns a compact shape by default: symbol-bounded ranges (signature plus the match),
  stateless `ref` handles that `open_range` expands, `generation` and `complete` once per response,
  and a hard `token_budget` that reduces bodies (full → signature → reference) without reordering.
  A range already sent on the connection comes back as a reference (`fresh_context: true` resends).
  `verbose: true` restores the previous shape. `repo_map` adds a ranked, budgeted `files` list.
- A stale `ref` returns `stale_handle` and no content.

**Concurrency and freshness**

- `midnight daemon start|stop|status`: one daemon per database serializes daemon writer calls through a FIFO write gate. `mcp` and `serve-http` start and use it
  automatically and fall back to in-process serving with a stderr notice; `MIDNIGHT_DAEMON=0` or
  `mcp --no-daemon` opts out. One-shot CLI commands are not routed through it yet.
- A native file watcher (FSEvents/inotify; no polling) refreshes changed files, reconciles after
  storms and branch switches and reports `index_status.watcher`. On by default in the daemon,
  `MIDNIGHT_WATCH=1` elsewhere.

**Memory and embeddings**

- Schema 10 records memory origin and a normalized-text digest; recall can layer project and global
  namespaces under the connection's policy and pack to a token budget. Writes suggest duplicates
  while retaining both observations. Current-time recall uses hybrid when eligible vectors and a
  permitted provider are available. Explicit lexical recall stays offline.
- New and changed code embeddings prefer Tree-sitter symbol boundaries. Unchanged files reuse their
  stored vectors. Cloud query embeddings gain a configurable
  timeout, classified failures and one bounded same-provider retry (never another provider).

**Experimental, not run:** Linux and Windows builds, the Windows handle-based source reads, and the npm
packages and workflows are staged but **NOT RUN**; they are not part of the supported platform set.
The daemon has no Windows transport.
