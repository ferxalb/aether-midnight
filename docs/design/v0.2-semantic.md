# 0.5 Semantic quality (design only in Part 1; implement in Part 2)

Read first: `src/embed.rs` (pins `MODEL_FILE_PINS`, `MODEL_REVISION`, RRF fusion, evidence-class
protection `code_evidence_class`), `src/cloud.rs` (timeouts, notices), `src/runtime.rs` (ORT pin),
`docs/embeddings.md`, `docs/hybrid-mcp.md`. **Exact path/symbol/literal-phrase protection in hybrid
fusion must stay untouched.**

## Decision record

**Chosen design**

1. *Symbol-boundary chunking.* Today vectors are per file (`code_knn` returns file-level hits). Part 2
   embeds per chunk: Tree-sitter symbol nodes (function/class/impl/method) with a leading doc comment,
   split at statement boundaries when a symbol exceeds the model window (target ≤ 256 tokens, hard
   ≤ 512), plus a file-level "header" chunk (imports + top comment); files with parse errors or no
   symbols use fixed windows of ~40 lines with 8-line overlap. Chunking runs inside the existing
   parse pipeline budgets (250 ms Tree-sitter, 1 MiB/file, in-flight byte budget): chunk extraction
   reuses the symbol table already produced by the parse and adds no second parse. Chunk rows store
   `(file_id, byte_start, byte_end, content_hash_of_file, ordinal)`; a file hit = max over its chunks,
   and the hit carries the best chunk range, which feeds Part 1's symbol-bounded ranges and handles.
   Schema change goes in schema 10 with memory (`v0.2-memory.md`).
2. *Candidate embedders* (to decide by a bake-off on the new labeled suite; license/size from web
   search results — **re-verify on each model card before pinning**):

   | Model | License | Params / dim | Notes |
   | --- | --- | --- | --- |
   | multilingual-e5-small (current) | MIT (**not re-verified**) | 118M? / 384 (dim verified in source) | multilingual, needs `query:`/`passage:` prefixes, not code-trained |
   | jina-embeddings-v2-base-code | Apache-2.0 (verified, vendor page) | 137M–161M (vendor pages disagree) / 768 (verified) | 8192 ctx, 30 programming languages; vendor marks it deprecated by newer models; ONNX export availability **not verified** |
   | CodeRankEmbed (nomic-ai) | MIT (HF card metadata) | 137M / dim not verified | 8192 ctx; needs a documented query prefix **not verified** |
   | jina-code-embeddings-0.5b | not verified | 0.5B / not verified | likely too large for RAM/load-time budget |
   | nomic-embed-code | not verified | 7B | rejected: size |

   Selection criteria, in order: license compatible with Apache-2.0 redistribution of *pins* (we never
   bundle weights; they are downloaded and checksummed), ONNX available or exportable without custom
   ops, dimension ≤ 768, int8 model ≤ ~150 MB, and measured recall on the new suite. Keep e5-small as
   the multilingual default unless a code model beats it on code queries *and* doesn't regress
   ES/EN natural-language queries; allow two pinned models selected by content type only if the
   suite shows a gain (vectors are keyed by model identity already).
3. *Prefixes.* Each model definition carries `query_prefix`/`passage_prefix` (e5: `query: `/
   `passage: `; code models: per model card). Prefix mismatch is the commonest silent quality bug, so
   the harness has a test embedding fixed strings against known cosines for each pin.
4. *int8 quantization.* Prefer the vendor's published int8/q8 ONNX; otherwise do not self-quantize in
   the product (no reproducible pin). Measure RSS and cold load for fp32 vs int8 (current: ~4 s,
   ~1.5 GiB — verified in docs; int8 numbers **not measured**) and quality delta on the suite;
   adopt int8 only if recall@10 drops ≤ 1 point absolute (starting threshold, tune from dev only).
5. *Pins.* Each model: repo, 40-hex revision, per-file SHA-256 and byte sizes (same shape as
   `MODEL_FILE_PINS`), verified at pull and at load. ORT pin per platform in `v0.2-platforms.md`.
6. *Cloud embedder transport.* Configurable query timeout (`config.json` `embed_timeout_ms`, default 5000,
   range 500–30000; bulk indexing keeps its own policy). Errors classified and surfaced verbatim in
   the notice: `dns`, `tls`, `timeout`, `http_<status>`, `auth`, `rate_limited`, `other` (today a
   generic notice groups them; `docs/rc6-real-repo-validation.md`: 10 of 17 probes degraded without
   a cause). One bounded retry for interactive queries only for `timeout`/`5xx`/`429`
   (with `Retry-After` ≤ 1 s), total wall budget = 2× timeout cap 10 s. Never a fallback to another
   provider; after the retry fails → lexical with the classified notice. Verify the `rainy-sdk`
   error types expose these classes (**not verified**; if not, classify from `ureq`/`native-tls`
   error text conservatively and label unknowns `other`).
7. *Labeled semantic suite.* `benchmark/suites/semantic_quality_v1`: queries with no lexical
   overlap with the target (paraphrase, intent, ES/EN), over a frozen fixture repo, hand-labeled
   relevant chunks, dev/held-out split fixed before evaluation, protected-class checks (an exact
   symbol/path/literal query must keep rank 1 under hybrid). Metrics: recall@k, MRR, protected-class
   rank unchanged, index time, RSS.

**Rejected**: self-hosted quantization in the product; per-language models in v0.2; reranker model
(extra RAM/latency; revisit after chunking); changing RRF constants (would alter frozen suites).

**Failure modes**: (1) chunk embeddings inflate index time/size → cap chunks per file (≤ 64), measure
bytes/vectors, keep file-level vector as fallback; (2) wrong prefix/pooling silently degrades →
cosine golden test per model; (3) cloud errors misclassified → unknown → `other`, never guessed.

**Confidence:** low-medium on model choice (no bake-off yet), high on chunking/prefix/transport
approach. **Would change my mind:** e5-small within 2 points of any code model on the suite → keep it
and skip the second model.
