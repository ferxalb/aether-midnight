## Shared decisions

1. **One library, thin adapters.** All new behavior lives in the library (`src/lib.rs` modules);
   CLI, stdio MCP, HTTP MCP and the daemon call the same functions (CLAUDE.md rule).
2. **Stateless handles, stateful sessions only as an optimization.** A handle is
   `path + line range + content-hash prefix`; it needs no server state, so it survives daemon
   restarts and the in-process fallback. Session state (what was already delivered) can only
   *shorten* a response, never change which evidence is true; losing it is always safe.
3. **Evidence classes are never reordered.** Ranking code is untouched. Packers choose *detail
   level per result* and where to cut the tail, never the order or membership of the head.
   Class order: exact path/symbol, literal phrase, rest.
4. **One token budgeting model** (`pack` in `code.rs`, reused by hybrid search and, in Part 2, by
   memory recall): fixed result order, per-result detail ladder
   (`full → signature+match → reference only`), hard cap = `token_budget`, estimator labeled as an
   estimate (`midnight-heuristic-v1`).
5. **Single writer per database = the daemon**, with a FIFO write gate inside it. Cross-process
   safety nets that exist today (index lock file, `busy_timeout`, `BEGIN IMMEDIATE` migrations)
   stay as the in-process fallback behavior.
6. **Same-user trust domain.** The daemon socket/pipe is user-only (0700 dir, 0600 socket; user-only
   DACL on Windows). `Policy` is evaluated daemon-side, per connection, from the policy sent in the
   handshake; it limits a model-facing front end, not a hostile same-user process (which could open
   the database file directly anyway).
7. **No silent degradation.** Watcher overflow/limit, daemon fallback, provider fallback, stale
   handles and partial coverage are all reported in the response or `index_status`.
8. **Additive, reversible changes.** New fields are additive; shape reductions are opt-out
   (`verbose`/`explain` restore the old shape) and listed as contract changes in `docs/api.md`.
   No schema change in Part 1 (schema stays 9); schema 10 is Part 2 (memory).
9. **Measurement rules** (AGENTS.md): release binary, one request in flight, `wait4` on the
   process that does the work (for the daemon, the daemon PID — the proxy's numbers are the proxy's
   only), paired against the base commit built once in a separate target dir, "not measured" when
   absent.

## Constraints that shaped the designs

- Claude Code warns above 10,000 MCP output tokens, limits to 25,000 by default, spills results over
  50,000 characters to a file, and backgrounds calls over ~2 minutes. Target: typical `search_code`
  ≤ 1,500 estimated tokens at default settings, hard cap `token_budget` ≤ 8,192 (below all limits).
- Adding the `notify` crate changes `Cargo.lock` (not currently present). That is a dependency
  decision with a one-time network resolve; see watcher doc §Dependency.
- Test code is not type-checked by `cargo check`; Part 1 tests are written but first compiled in
  the final phase, so each Part 1 commit says "tests written, not run".
