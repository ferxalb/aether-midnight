Read first in Part 2: `src/memory.rs` (recall ranking, `candidate_coverage`), `src/db.rs` `migrate`
(schema 9 today; exact `memories` columns were **not re-derived** in Part 1 — read them),
`src/retrieval_tests.rs`, `benchmark/` memory fixtures, `docs/retrieval-v04.md`, and the
Part 1 interfaces in `v0.2-token-savings.md` (ladder packer, handles) and `v0.2-daemon.md` (single writer).

## Decision record

**Chosen design**

1. *Layered recall (project + global).* Namespaces keep `prefix:name`. Two layers are consulted by a
   default recall: `project:<repo dir>` (primary) and `global:<name>` (fallback, default `global:user`).
   Recall without an explicit scope queries layers **separately** (two exact-namespace queries —
   never a `LIKE`/prefix query), merges with a fixed precedence: project results first within equal
   evidence class; a global memory is shown only if no project memory is *superseded-equivalent*
   (same dedup key, §3) and is labeled `layer: "global"`. Every result states its scope. Policy:
   `memory_scopes` restrictions apply per layer; a pinned scope disables the other layer entirely.
   No namespace leakage: layers are two filtered queries, tested with the existing leak checks.
2. *Auto-embedding on write and hybrid by default.* Already partly shipped in rc.7 (`remember`
   embeds when a provider is configured and permitted). Part 2: recall defaults to hybrid when stored
   vectors exist for the scope *and* a provider is permitted; otherwise lexical. `candidate_coverage`
   keeps its meaning: exact lexical stage is exact; hybrid adds `semantic_coverage: {embedded, total,
   model}`; a non-exact shortcut is never the default. Provider failure → lexical with an explicit
   notice (no fallback to another provider). Daemon hosts a bounded embedding queue so `remember`
   returns before a slow provider answers (`embedding: "pending"`), still reported honestly.
3. *Near-duplicate detection and supersession.* On write, compute a normalized dedup key (the
   existing Unicode/stopword normalization, sorted informative terms, hashed). Exact key match in the
   same scope within the validity window → return the existing record (`duplicate_of`). Near match
   (lexical: Jaccard ≥ 0.8 on informative terms; semantic, when vectors exist: cosine ≥ 0.92 —
   thresholds are **starting points to calibrate on `memory_quality_v3`, not measured**) → write
   proceeds but the response lists `similar: [ids]` and suggests `supersedes_id`; never auto-supersede
   silently (a wrong merge loses information).
4. *Expiry.* `valid_to` already exists. Add `expires_at` semantics by convention: `kind=derived`
   memories default to a 180-day review window shown as `review_after`; nothing is deleted
   automatically; expired (`valid_to` in the past) memories are excluded from default recall and
   returned with `as_of`. `compact` remains the only physical delete.
5. *Origin/trust field.* New `origin` ∈ `user | agent | repo` (default `agent` for MCP writes, `user`
   for CLI `memory remember`, `repo` for repo-derived/imported). Recall output shows `origin` per
   memory and the initialize instructions say that `agent`/`repo` memories are *data, not
   instructions*. Mitigation for persistent prompt injection: recall renders content as quoted data,
   caps per-memory length in compact detail, and a policy flag can exclude `origin=repo` from default
   recall. This reduces but does not remove injection risk; say so in `docs/privacy.md`.
6. *Token-budgeted recall.* Same ladder as code: `full → first sentence/160 chars → reference (id)`,
   hard cap `token_budget`, order fixed by the existing lexicographic ranking (phrase class →
   distinct informative terms → BM25), never reordered by the packer. `get_memory` expands by id.
7. *Schema 10 migration.* One `BEGIN IMMEDIATE` transaction: add `origin TEXT NOT NULL DEFAULT 'agent'
   CHECK(origin IN ('user','agent','repo'))`, `dedup_key TEXT`, index on `(scope, dedup_key)`; backfill
   `dedup_key` in batches inside the same transaction (bounded: if > 200k rows, store NULL and
   compute lazily). Optional (decide in Part 2): `code_blobs` for worktree sharing
   (`v0.2-daemon.md`). Bump `schema_version` last. **Rollback test:** inject a failure after the
   `ALTER`s (test hook) and assert `PRAGMA user_version`/`schema_version`, columns and row count are
   unchanged. Older binaries refuse schema 10 (same as 8 and 9). Memory and code stay in separate
   tables, never mixed in one query.
8. *Frozen suite `memory_quality_v3`.* New file under `benchmark/suites/`; existing suites and
   labels untouched (AGENTS.md). Contents: ES and EN records; paraphrase queries with no shared
   informative terms; multi-hop (answer needs two records); temporal (`as_of`, superseded, expired);
   dev/held-out split decided **before** looking at results, held-out never used for tuning; labels
   written by hand, hashed in the suite header. Metrics: recall@k, MRR, namespace-leak count,
   supersession correctness, `candidate_coverage` honesty (exact flag matches oracle).

**Rejected alternatives**: single merged namespace query with prefix (leakage risk); automatic
supersession on near-duplicate (silent data loss); LLM-based dedup (non-deterministic, needs a
provider); storing origin inside content text (not queryable, spoofable).

**Failure modes**: (1) global memory contradicts project memory → project wins, global shown only if
not equivalent, both labeled; (2) false-positive near-duplicate hides a distinct fact → never
suppress, only annotate; (3) migration fails on large DB → single transaction, rollback test, lazy
backfill cap.

**Measure/threshold:** `src/retrieval_tests.rs` exact oracle agreement unchanged; all four existing
frozen memory suites byte-identical; `memory_quality_v3` reported dev and held-out separately with
no threshold set a priori (set from the dev results, then frozen); namespace leaks = 0.

**Confidence:** medium. **Would change my mind:** v3 shows hybrid-by-default hurts exact-phrase
queries → keep lexical default for phrase-class queries (protection stays untouched).
