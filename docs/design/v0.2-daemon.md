# 0.3 Daemon / single writer (implemented in Part 1, Phase 3)

## Goal

Remove "two processes writing at once can fail with `database is locked`" structurally; load the
local model once; host the watcher and session state.

## Current state (verified in source)

`db::open` uses WAL, `busy_timeout` 5 s, foreign keys; migrations run in one immediate transaction;
`code.rs` takes a file index lock; `mcp::Session` holds `Rc<RefCell<…>>` state (memory session, query
cache, local model) and is not `Send`. `Policy::authorize` injects pinned memory scopes and restricts
tools/roots. stdio uses `read_bounded_line` (1 MiB). The local model costs ~4 s cold and ~1.5 GiB RSS
per process (`docs/v0.1-status.md`).

## Decision record: why a single writer

`busy_timeout` only bounds how long one writer waits (5 s). Indexing a large repository or
`compact` holds the write lock longer than that; a second writer then gets `SQLITE_BUSY`.
`BEGIN IMMEDIATE` avoids `SQLITE_BUSY_SNAPSHOT` upgrade failures (a read transaction trying to
become a writer, to which `busy_timeout` does not apply) but not waiting-time starvation, and SQLite
lock acquisition is not fair. A single writer process with a FIFO gate gives fairness, bounded wait
reported to the client, and a natural home for the model, the watcher and the session ledger.
Rejected: raising `busy_timeout` (hides, does not bound), retry loops in clients (duplicates policy,
unfair), SQLite `unlock_notify` (shared-cache only), a separate writer thread shipping closures
(requires rewriting every library function that opens its own connection).

**Chosen design**

- *Process model.* `midnight daemon run --db DB` (internal), plus `daemon start|stop|status`. One
  daemon per database file. A **write gate** (`WriteGate`: Mutex+Condvar ticket queue, FIFO) wraps
  every tool call classified as a writer (`index_repository`, `refresh_indexed_file`, `remember*`,
  `forget*`, `compact`, `embed`); readers run concurrently on per-connection SQLite connections
  (WAL). Inside the daemon no two writers contend, so `SQLITE_BUSY` cannot occur between clients.
- *Threads.* One OS thread per connection owning its own `Session` (it is `Rc`, not `Send`); no async
  runtime. Connection cap 32 (reject with a clear error). Part 2 correction: Part 1 used one slot per connection. With the Phase A change the local model lives in a daemon-wide
  `Arc<Mutex<Option<FastEmbedder>>>`, loaded on first semantic use; lexical paths never touch it.
- *Discovery and lock.* Files live in `<run_dir>`: `daemon.lock` (advisory `flock` via `fs2`, held
  for the daemon's lifetime), `daemon.json` (`pid`, `version`, `protocol`, `socket`, `started`).
  A stale lock cannot exist for `flock` (the kernel releases it on exit/crash); stale `daemon.json`
  and socket files are detected by failing to take the lock and removed by the next daemon. Run dir:
  Unix = `$XDG_RUNTIME_DIR/midnight` else `<config_dir>/run`, mode 0700, verified owned by the
  current user. Socket name = `d-<first 8 hex of sha256(canonical db path)>.sock` to stay under the
  macOS/Linux `sun_path` limit (~104/108 bytes); if the path is still > 100 bytes, use
  `/tmp/midnight-<uid>/` (0700, ownership verified). Socket mode 0600.
- *Transport trait.* `trait Transport { type Stream: Read+Write+Send; fn listen/connect }` with
  `UnixTransport` implemented now; `NamedPipeTransport` (`\\.\pipe\midnight-<hash>`, user-only DACL)
  designed in `v0.2-platforms.md`. Framing = existing JSON-RPC lines (1 MiB cap).
- *Handshake.* First client line: `{"midnight":"hello","protocol":1,"client_version":"…",
  "policy":{…}}`. Reply: `{"midnight":"ready","protocol":1,"daemon_version":"…","pid":N}` or
  `{"midnight":"error","code":"version_mismatch","daemon_version":"…","message":"…"}`. After `ready`,
  the stream is plain JSON-RPC lines identical to stdio. `protocol` differing → error, never
  undefined behavior. Same protocol, different crate version: allowed only if `protocol` equal and
  schema version equal; otherwise (daemon older/newer schema) → if the daemon has no other
  connections it is told to exit (`{"midnight":"shutdown_if_idle"}`) and the client respawns; if busy,
  the client gets `version_mismatch` and does **not** fall back in-process (a second writer would
  defeat the purpose) unless `MIDNIGHT_DAEMON=fallback`.
- *Policy per connection.* The `Policy` in the hello is the one the front end was started with
  (`--scope`, `--local-only`, HTTP token policy). The daemon constructs a `Policy` per connection and
  runs the unchanged `authorize`/`handle_message` path, so scope injection, memory-scope prefix
  rules and repo-root checks apply daemon-side. A connection cannot change its policy after hello.
  Two connections with different pinned scopes cannot see each other's memory (test).
- *Client behavior.* `midnight mcp` (stdio) connects, spawns the daemon if absent (detached via
  `setsid`/`process_group(0)`, `stdin/stdout` null, log file in run dir), waits up to 3 s for the
  socket, then proxies lines in both directions. If connect/spawn fails or `MIDNIGHT_DAEMON=0`
  / `--no-daemon`, it runs in-process exactly as today and prints one stderr line:
  `midnight: daemon unavailable (<reason>); running in-process` and sets `daemon: "in_process"` in the
  `initialize` instructions text so the agent/user can see it. HTTP transport and CLI subcommands that
  hit the DB use the same `daemon::client()` (read commands may stay in-process; write commands go
  through the daemon when one is running, never spawn one for one-shot CLI use).
- *Lifecycle.* Idle shutdown after `MIDNIGHT_DAEMON_IDLE_SECS` (default 600; `0` = never) with no
  connections and no watchers pending. Graceful shutdown on SIGTERM/SIGINT (`ctrlc` dep exists) or
  `daemon stop`: stop accepting, drain in-flight writes (max 10 s), `wal_checkpoint(TRUNCATE)`, remove
  socket and `daemon.json`, release lock. Crash recovery: SQLite WAL recovery is automatic; the
  next daemon removes stale socket/json; clients retry connect once after a failed handshake.
- *Existing tests.* Autospawn is on by default for `mcp`, so integration tests that spawn the binary
  would leak daemons. Decision: tests set `MIDNIGHT_DAEMON=0` through `tests/common` helper and
  daemon tests use a dedicated temp run dir (`MIDNIGHT_RUN_DIR`) and `MIDNIGHT_DAEMON_IDLE_SECS=2`
  plus explicit `daemon stop` in cleanup.
- *Worktrees.* Designed, **not implemented in Part 1**: share parsed artifacts (symbols, FTS terms)
  across worktrees of one `repo_id` by `content_hash`, via a new `code_blobs(content_hash, …)`
  table referenced from `code_files`. Needs schema 10 and touches the "code queries scoped by
  repo/worktree" invariant (queries would join blobs by hash but still filter `code_files` by
  worktree). Risk is not low (FTS rows are keyed by file id), so it is deferred to Part 2 with the
  schema-10 migration. Per-worktree indexes remain isolated.

**Rejected alternatives**: async runtime (tokio is present only for the cloud client; adding it to the
server doubles the concurrency model); one process-wide connection (serializes readers); SQLite-only
fixes (above); PID-file locking (stale PID reuse races; `flock` is atomic).

**Three most likely failure modes**

1. *Daemon killed mid-write.* SQLite transactions are atomic and WAL-recovered; client sees EOF,
   reconnects once (respawn) and the request is not auto-retried for writers (idempotent
   `operation_key` writes may be retried by the model). Test: kill -9 during `index`, then verify
   integrity and that the next client succeeds.
2. *Version skew after upgrade (old daemon still running).* Handshake mismatch → controlled restart
   when idle, clear error when busy. Test with a fake daemon announcing a different protocol.
3. *Zombie/leaked daemons or socket-path problems.* Idle shutdown, `daemon status/stop`, short
   hashed socket path, user-only permissions, ownership check of the run dir.

**Measurement and thresholds** (release binary, final phase; measure the **daemon PID** for RSS/CPU,
not the proxy)

- N=8 concurrent clients each doing 50 interleaved writes (`remember`) and `refresh_indexed_file`
  against one DB: **pass = 0 `database is locked` errors** (base commit: report observed count).
- Cold start (spawn → first response) p50/p95; per-request overhead vs in-process (n ≥ 200, one in
  flight) — **pass = ≤ 1 ms p50 added** for lexical search (not asserted a priori; report actual).
- RSS with local model: one daemon vs N processes — **not measurable on this host if the pinned
  runtime is absent** (see `docs/performance.md`); say "not measured" then.

**Confidence:** medium. The gate and handshake are straightforward; autospawn/test hygiene and
detached-process behavior on macOS are the risk. **What would change my mind:** if per-request
overhead is > 3 ms p50, add a pipelined binary framing only after measuring; if flock semantics
prove unreliable on a network home, document the run dir must be local.

## Implementation notes (Phase 3) — what was built, what changed

- Built: `src/daemon.rs` (server, client, `Transport`/`Stream`/`Listener` traits with a Unix socket
  implementation and an explicit "unsupported" stub elsewhere, FIFO `WriteGate`, `Backend` for HTTP),
  `mcp::run_session` (the stdio loop generalized to any reader/writer), `daemon start|stop|status|run`,
  `mcp --no-daemon`, `MIDNIGHT_DAEMON`, `MIDNIGHT_DAEMON_IDLE_SECS`, `MIDNIGHT_RUN_DIR`.
- **Policy `cwd` is a thread-local, not a `Policy` field.** The daemon's working directory is
  meaningless for a client, so the hello carries the client's `cwd`; `mcp::set_connection_cwd` stores it
  on the connection thread and `default_repo`/`path_arg` use it. (A `Policy` field would have broken
  every exhaustive `Policy {..}` literal.)
- **Version compatibility is protocol + schema**, not crate version: a newer client of the same wire
  protocol and database schema is served by an older daemon. Behavior differences between crate
  versions with equal protocol/schema are accepted risk; bump `PROTOCOL` when tool behavior changes
  incompatibly.
- **Idle shutdown ignores watchers.** With no connections the daemon exits after the idle period even if
  watchers exist; the next connection reconciles through the watcher catch-up.
- **Gate scope.** The gate is held for the whole writer tool call, including provider embedding calls in
  `index_repository`/`remember`. A slow provider therefore delays other writers by up to its timeout
  (5 s interactive). Moving embedding outside the gate is a Part 2 item (bounded embedding queue).
- **Not implemented:** CLI routing through the daemon; Windows named pipe; worktree row sharing (needs
  schema 10); automatic reconnect of a stdio session when the daemon dies (the proxy exits and the MCP
  client restarts it, which autostarts a fresh daemon); SIGTERM handling (the `ctrlc` dependency is built
  without the `termination` feature) — `daemon stop` is the graceful path and `kill` is the crash path.
- Tests written (not run): `tests/daemon.rs` (concurrent writers, kill -9 then recovery, stale
  lock/socket, protocol mismatch, per-connection policy isolation, in-process fallback), unit tests for
  the write gate and socket path/permissions. Existing spawn sites of `mcp`/`serve-http` now set
  `MIDNIGHT_DAEMON=0` so they never leak daemons.
